# Physics Playground

A static, bilingual collection of interactive mechanics experiments for introductory university students. Built with HTML, CSS, JavaScript ES modules, and SVG. No build step, packages, accounts, or external runtime services.

See [Changes](CHANGELOG.md) for the improvements recorded on November 10–11, 2026, including graph interaction, guided quizzes, achievements, theme styling, and typography.

## Run locally

Use Node.js 18+ and Python 3:

```sh
npm run dev
```

Open http://127.0.0.1:8000/. ES modules require an HTTP server; opening the HTML file directly will not work. Only `public/` is served. To check a GitHub Pages project subdirectory:

```sh
python3 scripts/serve.py --port 8000 --base-path /physics-playground/
```

Open http://127.0.0.1:8000/physics-playground/. Direct experiment links use `#/basketball` and `#/pulley`, so a reload requires no server routing rules.

## Use

Choose an experiment, change its sliders or numeric fields, and press Play. Pause, advance by 0.05 simulated seconds, reset, or choose quarter-speed playback. Changing physical parameters resets time. Restore defaults resets the physical parameters too. Language changes preserve the current experiment, parameters, and playback state; the language preference is stored locally when storage is available.

Basketball has an optional equal-time trail in “Make it your own”: dots mark positions every 0.1 simulated seconds, revealing constant horizontal spacing and changing vertical spacing. The trail is off by default. Basketball has speed and angle controls, with heights and distance in the advanced panel. Its previous observed trajectory can remain visible for comparison. The fixed pulley allows changing both masses and releasing them from rest. Motion and graph cursors follow animation frames. Numeric readouts refresh at 10 Hz during playback and immediately on pause, step, reset, or inspection; unchanged control and equation nodes are reused. Basketball trajectory geometry is sampled once per parameter change and revealed with a clip during flight. No experiment autoplays. Playback pauses when the tab is hidden. Keyboard users can use native slider arrows, number inputs, and buttons; reduced motion users can advance with Step.

The Basic collection also includes `#/double-spring` and `#/carousel`, each with its own bilingual intuition quiz. The two-spring oscillator adds the forces from opposite identical springs: F = −2kx, ω = √(2k/m), with release displacement x₀ = l − d. The carousel shows a steady conical pendulum from the side and above: T cos α = mg and v = √(Rg tan α). Radius and angle controls select a new steady orbit and determine the required string length. Select either system’s mass to inspect its forces and derivation. Both stop after four cycles for observation.

To hide the carousel’s fading trail, set `carouselConfig.showTrail` to `false` in `public/js/config.js`. It defaults to `true`. The trail uses the bob’s green hatching and pencil edges in notebook mode; switching styles updates it immediately.

Three further Intermediate systems explore circular motion: `#/rotating-tube`, `#/two-string`, and `#/energy-bowl`. Each includes English/Hebrew controls, selectable force analysis, a derivation, motion graphs, and its own intuition quiz. The rotating tube checks the static-friction bound and shows maximum frequency and radius. Its synchronized top and side views show the same steady orbit; selecting either mass overlays the forces. The side view projects radial friction into the viewing plane, using ⊗/⊙ for its depth direction at quarter turns. The equal-string system starts at 1 Hz and derives geometry and both tensions; a horizontal reference and right-angle marker make the side-view angle explicit. Geometry controls keep `0 < d < 2ℓ`. Configurations that would exceed available static friction or require a negative lower tension show a frozen diagnostic diagram and explain the model boundary; subsequent sliding or slack-string motion is not modeled.

The smooth bowl uses the full nonlinear equation `θ̈ = −(g/R)sin θ`, with release from rest at up to 90°. A cached dimensionless quarter-orbit table, integrated with RK4 and timed with the elliptic-integral period, is sampled independently of animation frames. Speed follows energy conservation. The energy bar sits directly beneath the bowl inside the stage, above the playback controls. “Resolve forces along radial and tangential axes” replaces weight with its signed components −mg cos θ and −mg sin θ, while keeping N inward; the axes follow the body. The two-color bar uses the site’s sage green for kinetic energy and the bob’s warm clay for gravitational energy. Its three mathematical readouts, `E_k`, `E_g`, and `E_tot`, share a single line, with values in joules. It keeps a fixed total length; `E_g = mgR(1 − cos θ)` is zero at C and `E_k = E_tot − E_g`. A/B/C mark the rim, 30°, and bottom. Readouts distinguish signed tangential acceleration from inward centripetal acceleration. The derivation uses the question’s zero-height reference at A: `E_g^(A) = −mgR cos θ`, so release from A gives `E_tot^(A) = 0`. It substitutes R = 1 m and g = 10 m/s² to solve the radial and tangential acceleration magnitudes at A, B, and C. A reference-shift equation relates this to the bar’s zero at C. The bar follows the current language, theme, and notebook treatment.

## Intuition quizzes and achievements

Every demonstration has ten English/Hebrew questions, including six new conceptual questions. Questions emphasize forces, motion, parameter comparisons, energy, and graph interpretation. Ordinary sets contain five questions, favoring unseen questions and independent reviews of missed concepts. “Practice all questions” opens the entire bank in order. Each answer has its own misconception feedback; hints, retries, and the full explanation are available without time pressure. Results separate first-attempt predictions or answers from solutions reached with help.

Each demonstration has three permanent milestones:

- **Explorer:** finish a question set.
- **Investigator:** earn Explorer and complete every experiment challenge by recording a prediction, running both setups, and answering the explanation question correctly.
- **Mastery:** earn Investigator, answer all ten questions without help across any number of sets, and resolve missed concepts with a different question on the same concept.

Collection cards show up to three stars: Explorer (one bronze star), Investigator (two silver stars), and Mastery (three gold stars). Earned stars and demonstration frames share the same metal finish, including the compact journey tiles. The journey layout adapts to phone widths and Hebrew reading direction. The visual Physics Journey dashboard uses a completion ring, progress bars, compact demonstration tiles, and four subject badges plus a final collection badge. Requirements are available on demand under “How to earn stars” and in icon tooltips. Previously earned stars carry forward as Explorer stars; saved badge data is preserved. Progress, selected answers, hints, and active sessions are saved locally in this browser; blocked storage falls back to the current visit. No account, remote service, streak, or timer is involved.

All demonstrations include at least one **Predict → Observe → Explain** challenge; spring and pendulum each have three, and double-spring has two. The “Experiment challenges” button makes them directly accessible. The challenge first highlights the one parameter that changes between A and B. After a prediction, a persistent coach beneath the canvas guides both runs, with play/pause controls, progress, replay, and cycle-time comparisons. Cyclic systems play one full cycle; other systems run to their observation cutoff. The scene pauses automatically at completion. A separate reasoning question then asks why the result occurred, with answer-specific feedback and the original prediction preserved. Full setup details remain available on demand. Experiments restore defaults before applying the stated settings, and changing a parameter mid-run requires replaying that setup for a fair comparison. Ordinary questions may still be answered without running the experiment.

Run `npm test` and `npm run check` for the automated checks. For native browser click tests, install Firefox and run `npm run test:browser` (or set `FIREFOX_BIN`). This dependency-free browser test uses an isolated temporary profile, loads a local server, verifies visible spring experiment animation, checks persistence after refresh, and exercises Hebrew controls at mobile width. It does not use the DOM fixture or synthetic click dispatch.

## Optional notebook style

Simulation canvases follow the site theme in both illustration styles. SVG surfaces, guides, body labels, force arrows, and label outlines use shared `--scene-*` color variables, with the original light palette as fallbacks. Theme changes update the artwork without rebuilding the scene or resetting playback. Run `npm run test:canvas` to check live theme switching and rendered text/force contrast across all 14 systems; add `-- --artifacts /tmp/canvas-preview` to save screenshots.

The notebook button beside the dark-mode button switches styles immediately, preserving the current simulation, parameters, and playback. Your selection is saved locally when storage is available. The current design stays the default for new visitors. Preview the notebook sketch treatment at `http://127.0.0.1:8000/?style=notebook` (or `?style=notebook#/basketball`). Use `?style=current` to compare. The override follows navigation between experiments and works with both languages and light/dark mode.

To enable it by default, set `presentationConfig.illustrationStyle` to `'notebook'` in `public/js/config.js`. Set it back to `'current'` to restore the current design. The opt-in stylesheet, precomputed SVG pencil outlines, hatched body fills, and separate catalog illustrations change presentation only; simulation models and plot data are shared. Existing illustration assets are retained. Notebook mode uses no live noise or displacement filters. Sketch outlines are created once when scenes are built and move with their objects; changing geometry during playback keeps a plain SVG stroke. Regenerate the filter-free notebook catalog artwork with `python3 scripts/bake_notebook.py`, then run `python3 scripts/bake_dark_illustrations.py` to rebuild the dark variants in `assets/dark/` and `assets/notebook/dark/`. Both generators include all catalog systems. Catalog images and their backgrounds switch immediately with the site theme, including when changing illustration styles in dark mode.

## Interface typography and theme styling

Regular and notebook modes share the UI font stack defined by `--font-ui` in `public/styles/main.css`: Arial, Noto Sans Hebrew, then the browser’s sans-serif fallback. Headings, controls, ordinary diagram labels, graph tick labels, counters, metrics, and the footer use this stack. Numeric counters and readouts use tabular digits for stable alignment. The separate `--font-math` token uses the bundled Latin Modern Math face for equations, MathML, and physical quantity symbols. Keep prose in the UI font when adding components; use the math token only for mathematical content.

The header pendulum mark also switches between a crisp regular badge and a hatched notebook drawing. ## Models and developer configuration

Set `gravity` in `public/js/config.js` to change gravity manually for both models. It defaults to 10 m/s²; there is no student-facing gravity control. Use a finite, positive value.

- Basketball uses constant-gravity analytic projectile motion, no drag, a point particle, and no bounce. Time ends at ground contact. A successful shot crosses the hoop's horizontal coordinate on descent within 0.12 m of its height. Ball and rim artwork do not represent collision geometry. There is no physical capture at the hoop; the analytic trajectory continues to the ground.
- The pulley has a massless, frictionless fixed wheel and taut massless rope. Both masses start from rest. Acceleration and tension follow the two-mass Newton equations. Each mass can travel 1.25 m from its starting position before the experiment freezes; no collision or subsequent dynamics are modeled. Equal masses stay at rest during the four-second observation window. The readouts show travel magnitudes; feedback gives direction.
- Models are sampled at elapsed simulated time rather than advanced with frame-dependent numerical integration.

In the pulley experiment, click or tap either mass (or focus it and press Enter/Space) to open its body analysis below the simulation. Selection shows thick, horizontally centered tension and weight arrows directly on the mass in the simulation and pauses playback without changing time; Play continues with the analysis open. Close or Escape dismisses the panel and returns focus to that mass. Selection and the optional substitution/solution expansions survive parameter edits, reset, and language changes. Leaving the experiment clears them.

The force arrows follow the selected mass during playback and use one linear scale shared by both bodies. The equations below state the positive axis: downward on the left and upward on the right. There is no separate force diagram. Equations use native MathML with a bundled Latin Modern Math font for TeX-style typesetting, proper fractions, subscripts, and powers. The font is served locally; its license and attribution are in `public/assets/fonts/`. Symbolic Newton equations precede optional current-value substitutions and a symbolic coupled-system derivation; “Solve the system” contains no numerical substitutions. At the travel cutoff the panel explains that the ideal motion equations do not model a collision or equilibrium. Time graphs support pointer and keyboard scrubbing; tools for solving basketball launch parameters remain deferred.

In basketball, select the ball by click, tap, or Enter/Space to see its launch components and horizontal/vertical equations of motion. A small +x/+y marker shows the fixed coordinate directions. The optional “Derive the trajectory” section eliminates time to obtain the symbolic parabola equation, without numerical substitutions. Selection pauses playback; Play continues with the equations open. Canvas clicks outside the ball, Close, and Escape dismiss the analysis. Selection and the derivation expansion survive scene rebuilds, parameter changes, resets, and language changes. The selected outline stays fixed while the decorative ball artwork rotates. At ground contact, the panel explains the model cutoff.

The third system, **Inclined plane with friction / מישור משופע עם חיכוך**, is available at `#/incline`. It uses the section 1.3 example from `Material/Tirgul3.pdf`: a 3 kg block, μₛ = 0.2, μₖ = 0.1, and a 30° slope. Controls vary mass, angle, and both friction coefficients; editing a coefficient adjusts its counterpart when needed to preserve μₖ ≤ μₛ. Every parameter edit restarts the block from rest. Static friction balances the downhill weight component up to its limit; above the critical angle the block slides with acceleration g(sin α − μₖ cos α). The readouts show displacement, acceleration, and critical angle. Select the block to pause playback, show weight/normal/friction arrows on the moving body, and open the symbolic threshold and acceleration derivations. Language switching and parameter edits retain selection. Playback ends after 4 m of travel, or 4 s for a resting block; no collision is modeled. The source document stays outside the served public directory.

Two harmonic oscillator systems are available from the catalog:

- **Small-angle pendulum / מטוטלת בזוויות קטנות** (`#/pendulum`): adjust bob mass, string length (0.5–3 m), and initial angle (1–15°). Released from rest, the bob follows θ(t) = θ₀ cos(√(g/L)t). Angular velocity is reported in rad/s; the displayed angle and input use degrees. The dynamics and conserved energy use the small-angle approximation, while the drawing follows a circular arc. The tangential restoring-force arrow is approximate and does not represent the total force, which also includes the radial component.
- **Horizontal mass–spring oscillator / מתנד מסה–קפיץ אופקי** (`#/spring`): adjust mass, spring stiffness (1–100 N/m), and initial displacement (0.05–1 m). Released from rest on a frictionless horizontal surface, the mass follows x(t) = A cos(√(k/m)t). The spring visibly compresses and stretches around its natural length; a dashed line marks equilibrium.

Both oscillators use analytic time sampling without damping or driving. Select the moving body to pause playback and open symbolic derivations of the restoring equation, cosine solution, velocity, and period. Play resumes with the analysis open; Escape or Close dismisses it. Selection and the expanded derivation survive edits, resets, and language changes. Each run ends after four periods as an observation cutoff, rather than a physical stop. Tests check phase, turning points, energy conservation, parameter dependence, selection, localization, and cleanup.

The **Accelerating elevator / מעלית מאיצה** (`#/elevator`) has a person standing on a scale. Adjust mass (15–150 kg, default 60 kg) and signed constant acceleration (−g to +g, default +2 m/s²). Upward is positive: ΣFᵧ = N − mg = ma, hence N = m(g + a). At a = −g the normal force and scale reading are zero; acceleration below free fall is excluded. Each run starts from rest and ends after a four-second observation window without modeling braking or impact. The cabin stays centered while shaft markers move relative to it. Displacement, velocity, and acceleration graphs use the Earth frame. Select the person for proportional normal/weight arrows, symbolic equations, optional numerical substitution, and the normal-force derivation. Selection pauses playback; Play resumes with analysis open. Keyboard selection, Close/Escape, language switching, reset, and parameter edits follow the other demonstrations.

## Intermediate friction systems

The collection has **Basic systems** and **Intermediate systems** tabs (מערכות בסיסיות / מערכות ברמת ביניים). Open `#/intermediate` for three coupled systems based on questions 1–3 of the local friction handout:

- `#/friction-stacked`: equal stacked masses, static coefficient 3μ between blocks and kinetic coefficient μ at the floor. Both blocks start from rest by default. The solution derives the floor load 2mg, required inter-block friction, and slip threshold Fcrit = 8μmg. Above the threshold the blocks slide relative to each other: an added adjustable inter-block kinetic coefficient μₖ,ₜ defaults to 0.2 and is constrained to 0 ≤ μₖ,ₜ ≤ 3μ. The upper acceleration is μₖ,ₜg and the lower acceleration is (F − 2μmg − μₖ,ₜmg)/m. With optional initial speed they start together; their separate trajectories, accelerations, relative displacement and graph curves make sliding visible. “Watch the slip slowly” replays at quarter speed. Motion ends at 0.75 m relative slip (before loss of support), 2 m lower-block travel, rest, or four seconds. Falling and tipping are not modeled. The added kinetic coefficient does not change the static threshold or quiz answers.
- `#/friction-table`: a rough horizontal table connected over an ideal pulley to a smooth slope. With m₂ already sliding downhill, a = g(m₂ sin α − μm₁)/(m₁ + m₂) and T = m₁m₂g(sin α + μ)/(m₁ + m₂).
- `#/friction-hanging`: a hanging mass connected to a rough slope. When bonus initial speed is added, choose its sliding direction. Positive coordinates are m₁ upward and m₂ downhill; a = g[m₂(sin α ∓ μ cos α) − m₁]/(m₁ + m₂), using minus for downhill sliding and plus for uphill sliding. T = m₁(g + a). Friction follows velocity even when acceleration opposes it. “Solve the system” also derives static equilibrium: |m₂ sin α − m₁| ≤ μₛm₂ cos α, or m₂(sin α − μₛ cos α) ≤ m₁ ≤ m₂(sin α + μₛ cos α), with a = 0 and T = m₁g. The derivation distinguishes the general static coefficient from the simulation’s release assumption μₛ = μₖ.

Each system includes bilingual controls, animation, motion graphs, an expandable worked solution, and ten conceptual questions about forces, friction, rope constraints, and the distinction between velocity and acceleration. Select either body by click, tap, Enter, or Space to pause and show its force arrows on the moving body plus its Newton equations and current force magnitudes. Play continues with the analysis open; Close or Escape returns focus. Selection and expanded analysis survive parameter edits and language changes. The pulley ropes use exact circular arcs and tangent segments, preserving rope length as bodies move and angles change. Rough contact surfaces have diagonal hatch marks, while the smooth slope stays unhatched. The canvas keeps body symbols, the angle arc, the applied-force arrow and friction coefficients beside the surfaces; mass and initial-speed summaries stay in the parameter panel. Intermediate mathematics is authored in LaTeX and rendered locally as MathML, including fractions, subscripts, and trigonometric functions; the supported notation lives in `core/latex.js`. Each “Solve the system” section also calculates acceleration using the current parameters, with numerical substitutions, units, the applicable static/sliding regime, and both block accelerations during relative slip. These calculations update with parameter edits and language changes while preserving expanded sections. All three systems start from rest with defaults that produce nonzero acceleration (the hanging mass defaults to 3 kg). A collapsed “Bonus: initial motion” section offers optional initial speed (default zero), plus the hanging system’s initial direction when its speed is nonzero. For release from rest, the supplied floor/table/slope coefficient is also used as the limiting static coefficient; this additional simulation assumption is stated in both languages. Static friction can hold the system at rest. Otherwise the hanging system starts in the direction selected by the force imbalance. Quiz questions describe the models and do not change with sliders. The moving branches stop at the earlier of rest, 2 m travel, or four seconds; release can remain in static equilibrium; reversals after stopping, collisions, falling, and tipping are not modeled. Stacked-block sliding uses the explicitly added kinetic coefficient and has the earlier support cutoff described above. The original handout remains outside the public directory.

## Project structure and adding a system

`public/js/registry.js` is the catalog's source of truth. The app and router contain no individual-system logic. Shared code in `public/js/core/` handles the clock, controls, layout, and translation of common interface text.

To add a system:

1. Create `public/js/demos/<id>/physics.js`, `strings.js`, and `index.js`. Keep physics pure and supply gravity explicitly rather than reading hidden model constants.
2. Export `mount({ root, lang })` from `index.js`. It must return `{ reset(), setLanguage(lang), dispose() }`. Use `createExperiment` for the common simulation layout, clock, and controls. Its render callback receives simulated time. Register every event listener with the shell's `signal` so disposal removes it; `api.dispose()` cancels animation and removes the layout. Use a new, module-specific SVG ID prefix for patterns and clips.
3. Keep live state in the mounted instance. Language changes update labels without rebuilding or resetting the instance. Put system-specific Hebrew and English text in `strings.js`; common text lives in `core/i18n.js`. Keep the physical diagram's left/right coordinates independent of interface text direction.
4. Add an illustration in `public/assets/` and a registry entry with a unique stable ID, number, bilingual title/description/tags, topic key, image path, and lazy `load()` function. Use an existing shared topic key, or add its translations in `core/i18n.js`. Catalog cards and `#/<id>` routes appear automatically.
5. For a force-based system, use `createBodyAnalysis` from `core/body-analysis.js` with a unique ID and the shell's `stageColumn` and `signal`. Supply stable body IDs, localized titles, two vertical force vectors (tension then weight for the pulley), a common linear scale, the positive-axis direction, accessible force descriptions, and authored symbolic/numeric solution steps. Render force overlays in the simulation itself; the shared panel displays equations. Keep these data in a demo-specific module such as `demos/pulley/analysis.js`, using the existing physics model as the source of truth. The panel preserves expansion state while updating content and avoids redrawing unchanged analysis during animation. Handle selection, pausing, focus return, and reset policy in the demo. The shared panel also accepts optional `groups` of equations and can omit `numeric` entirely, as in `demos/basketball/analysis.js`. Its `solution` expansion holds the optional symbolic derivation. Use the shared MathML helpers for authored fractions, subscripts, powers, and upright trigonometric functions. When rebuilding SVG objects, delegate events to the stable SVG root or abort per-scene listeners to avoid retaining detached objects.
6. Add tests for known physical results, conservation/constraints, alternative gravity, and boundary cases. Document model assumptions and travel limits in both languages.

The collection can grow without editing existing demos or navigation. Topic grouping and search can be added when the catalog becomes large enough to need them.

## GitHub Pages

Publish the repository to GitHub, using `main` as the default branch (or update `.github/workflows/pages.yml`). Under **Settings → Pages → Build and deployment**, select **GitHub Actions**. Pushes and pull requests run validation only. When you are ready to publish, manually run the workflow on `main` from the Actions tab; it runs checks and tests, then uploads **only `public/`** and deploys it. The workflow follows [GitHub's custom Pages workflow guidance](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

Private development inputs and internal planning files are ignored by Git and are outside `public/`. Do not force-add those files or deploy the workspace root. If any private file was already committed elsewhere, ignoring it does not remove its history; keep it out of the public repository before publishing.

No license has been selected yet. Choose a license before inviting reuse or contributions.

Quiz prompts, answer options, and explanations use authored `$...$` LaTeX spans in both languages, rendered locally as inline semantic MathML. Fractions, roots, powers, subscripts, Greek symbols, and upright units use the same renderer as the force derivations. Keep mathematics inside these spans when adding questions; prose stays in the interface font and Hebrew text retains its direction.
